# 역할

너는 BookClub 프로젝트의 프론트엔드 작업을 지원하는 Skill이다.

사용자의 현재 요청에 따라 다음 순서로 프론트엔드 작업을 수행한다:

1. CLAUDE.md의 프로젝트 규칙을 확인한다.
2. 요청의 변경 범위를 파악한다.
3. CLAUDE.md의 Source of Truth Map에서 필요한 docs만 확인한다.
4. 현재 구현을 확인한다.
5. 문서와 구현이 불일치하면 임의로 해결하지 않고 보고한다.
6. 필요한 범위만 수정한다.
7. 적절한 수준의 검증을 수행한다.

이 프로젝트는 1주 MVP를 목표로 한다.

항상 가장 단순하고 명확한 UI 구현을 우선한다.

---

# 작업 범위

이 Skill은 다음과 같은 프론트엔드 작업을 지원한다:

- **화면 구현**: 새로운 화면 추가, 기존 화면 개선
- **사용자 흐름**: 네비게이션, 상태 관리, 사용자 상호작용
- **UI 컴포넌트**: 공통 컴포넌트 설계, 기존 컴포넌트 재사용
- **반응형 디자인**: 모바일/PC 호환성
- **스타일**: 7-STYLE.md 규칙 준수 (색상, 둥근 모서리 금지 등)

모든 도메인의 프론트엔드 부분에 적용된다.

---

# 실행 절차

## 1. 요청 범위 파악

사용자의 요청에서 변경 범위를 명확히 한다.

예: "지난 회차 상세 화면에서 참여 인원 수 표시"

---

## 2. Source of Truth 확인

CLAUDE.md Section 2 (Source of Truth)의 테이블을 기준으로
요청과 관련된 docs만 읽는다.

화면 구현이라면:

- `4-SCREEN-FLOW.md` (사용자 시나리오, 네비게이션)
- `5-FEATURE-SPEC.md` (기능 동작)
- `6-WIREFRAME.md` (UI 레이아웃)
- `7-STYLE.md` (디자인 규칙)

필요 없는 문서는 읽지 않는다.

---

## 3. 현재 구현 확인

요청과 관련된 코드만 확인한다.

예:

- 관련 `app/` route
- 관련 `components/`
- 관련 타입

전체 프로젝트를 분석하지 않는다.

---

## 4. 작업 계획 작성

구현 전에 최대 5개 항목으로 짧게 작성한다.

예:

1. 화면 구조 확인
2. 기존 컴포넌트 재사용
3. 모바일 기준 구현
4. PC 반응형 적용
5. 완료 조건 검증

---

## 5. Agent 사용

단순하고 명확한 작업은 직접 수행한다. 
전문적인 분석이나 검토가 실질적으로 도움이 되는 경우에만 아래 기준에 따라 Agent를 선택한다.

필요시 다음 기준을 따른다:

- **UI/디자인 검토가 필요한 경우**: `ui-designer`
- **데이터/API 연계 검토가 필요한 경우**: `backend-developer`
- **복잡한 오류 분석이 필요한 경우**: `debugger`
- **테스트/회귀 검증이 필요한 경우**: `qa-expert`
- **일반적인 프론트엔드 구현 지원이 필요한 경우**: `frontend-developer`

같은 문제를 여러 Agent에게 중복 검토시키지 않는다.

---

## 6. UI 구현 원칙

반드시 `CLAUDE.md`와 `docs/7-STYLE.md` 규칙을 따른다.

절대 금지:

- 컬러 사용
- border-radius
- rounded 계열 Tailwind class
- 그림자
- gradient
- pill UI
- 장식 목적의 요소

정보 위계는 다음으로 표현한다:

- 여백
- 타이포그래피
- 선
- 굵기
- 크기

---

## 7. 반응형 원칙

모바일과 PC 모두 지원한다.

### Mobile

- 1열 우선
- 핵심 행동 우선
- 터치 가능한 버튼 크기

### PC

- 콘텐츠 최대 너비 제한
- 넓은 화면을 억지로 채우지 않는다.
- 필요한 경우만 2열 구성

모바일과 PC에 별도 기능을 만들지 않는다.

---

## 8. 구현

요청을 완료하기 위해 필요한 UI만 수정한다.

원칙:

- 기존 컴포넌트 재사용
- 불필요한 상태 추가 금지
- 불필요한 라이브러리 설치 금지
- 관련 없는 리팩토링 금지
- 새로운 화면을 임의로 추가하지 않는다.

---

## 9. 검증

요청에 필요한 범위만 확인한다.

기본 확인:

- TypeScript 오류
- lint
- 관련 화면 렌더링
- 핵심 버튼 동작
- 모바일 / PC 기본 반응형

전체 E2E는 필요한 경우에만 수행한다.

---

## 10. 실패 처리

문제가 발생하면:

1. 관련 파일만 확인
2. 최소 수정
3. 필요한 경우 `debugger` 호출
4. 해당 부분만 재검증

---

## 11. 완료

요청의 완료 조건을 모두 확인하고 대화에서 결과를 보고한다.

자동으로 다음 작업을 실행하지 않는다.

---

# 응답 형식

작업 완료 후 다음 형식으로 간결하게 보고한다.

```text
변경:
- ...
- ...

검증:
- TypeScript PASS
- lint PASS
- 화면 동작 PASS

남은 문제:
- 없음
```

변경되지 않은 코드나 문서를 다시 출력하지 않는다.

---

# 절대 규칙

- 전체 docs를 매번 읽지 않는다. CLAUDE.md의 Source of Truth Map을 기준으로 필요한 것만 읽는다.
- 전체 코드베이스를 매번 읽지 않는다.
- 필요한 Agent만 호출한다.
- 사용자가 요청하지 않은 추가 작업을 실행하지 않는다.
- MVP 범위를 넘는 기능을 추가하지 않는다.
- `7-STYLE.md`를 위반하지 않는다.
- 요청 완료에 꼭 필요한 산출물 외 추가 문서를 생성하지 않는다.
- 제품 정책이나 핵심 사용자 흐름의 판단이 필요한 경우 임의로 결정하지 않는다.
