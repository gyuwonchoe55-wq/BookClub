# 스타일 가이드

## 1. 디자인 방향

서비스는 독서와 대화에 집중할 수 있도록 최대한 단순하고 차분하게 디자인한다.

핵심 키워드:

- Minimal
- Clean
- Calm
- Typography-focused
- Generous whitespace
- Square / Sharp

장식적인 UI보다 텍스트, 여백, 선을 활용해 정보의 위계를 표현한다.

전체 UI는 직선과 사각형을 기본 형태로 사용한다.

---

# 2. Color

컬러를 사용하지 않는다.

기본적으로 다음 요소만 사용한다.

- 흰색 배경
- 검정색 텍스트
- 검정 또는 회색 계열의 Border
- 보조 정보에 한해 회색 텍스트

버튼, 카드, 진행 상태 등을 구분하기 위한 별도의 포인트 컬러를 사용하지 않는다.

상태 표현이 필요한 경우 색상이 아니라 다음 방법을 우선한다.

- 굵기
- Border
- 명암
- 아이콘
- 텍스트
- 형태 변화

---

# 3. Shape

## 라운드 UI 사용 금지

모든 UI 요소는 직선과 사각형을 기본으로 한다.

`border-radius`를 사용하지 않는다.

다음 요소에도 둥근 모서리를 적용하지 않는다.

- Button
- Input
- Textarea
- Card
- Modal
- Dialog
- Dropdown
- Badge
- Tooltip
- Progress UI
- 기타 Container

Pill 형태의 UI도 사용하지 않는다.

디자인 라이브러리나 브라우저 기본 스타일에 `border-radius`가 적용되어 있다면 제거한다.

---

# 4. Typography

텍스트 자체가 화면의 주요 시각 요소가 되도록 한다.

### 제목

- 굵고 명확하게 표현
- 화면의 핵심 메시지를 짧게 전달
- 필요하면 2줄 사용 가능

예:

> 어떤 독서모임을  
> 만들러 오셨나요?

### 본문

- 읽기 편한 크기 사용
- 과도하게 작은 글씨 사용 금지
- 긴 설명보다 짧고 자연스러운 문장 사용

### 보조 정보

입력 글자 수, 진행 순서 등 부가 정보에만 작은 크기와 회색 계열을 사용한다.

---

# 5. Layout

전체적으로 충분한 여백을 사용한다.

- 콘텐츠는 화면 중앙을 기준으로 배치
- 콘텐츠 최대 너비를 제한
- 요소 사이 간격을 충분히 확보
- 화면을 박스와 카드로 과도하게 나누지 않음
- 정돈된 수직/수평 정렬 유지

모바일에서는 좌우 여백을 유지한 1열 구조를 기본으로 한다.

PC에서도 콘텐츠를 화면 전체 너비로 늘리지 않는다.

넓은 화면의 빈 공간을 억지로 채우지 않고 여백으로 활용한다.

---

# 6. Input

입력창은 단순한 사각형 형태를 사용한다.

- 흰색 배경
- 얇은 Border
- `border-radius: 0`
- 충분한 내부 여백
- 그림자 사용 금지

Placeholder는 실제 입력값보다 약하게 표현한다.

입력창의 크기와 형태는 서비스 전체에서 일관되게 유지한다.

---

# 7. Button

버튼은 단순한 사각형으로 표현한다.

- `border-radius: 0`
- Border 사용
- 충분한 높이
- 명확한 텍스트
- 그림자 사용 금지
- 포인트 컬러 사용 금지

Primary Action이라고 해서 별도의 컬러를 사용하지 않는다.

중요도는 다음 요소로 표현한다.

- 크기
- 위치
- Border 굵기
- 텍스트 굵기

한 화면에서 Primary Action은 가능하면 하나만 강조한다.

---

# 8. Card

카드는 꼭 필요한 경우에만 사용한다.

예:

- 현재 모임
- 현재 질문
- 독서 기록

카드가 필요한 경우:

- 사각형 사용
- `border-radius: 0`
- 흰색 배경
- 얇은 Border
- 그림자 사용 금지

정보 구분이 여백만으로 충분하다면 Card와 Border 자체를 사용하지 않는다.

---

# 9. 진행 화면

모임 진행 화면에서는 현재 이야기하고 있는 콘텐츠가 가장 눈에 띄어야 한다.

우선순위:

1. 현재 문장 또는 질문
2. 현재 STEP
3. 작성자
4. 진행 상태 / 타이머
5. 다음 행동

진행 중에는 네비게이션이나 관리 기능 등 불필요한 요소를 최소화한다.

현재 콘텐츠를 큰 타이포그래피와 충분한 여백으로 강조한다.

---

# 10. Responsive

모바일과 PC 모두 동일한 디자인 언어를 사용한다.

### Mobile

- 1열 구조
- 충분한 좌우 여백
- 터치하기 쉬운 버튼 크기
- 핵심 콘텐츠 우선

### PC

- 콘텐츠 최대 너비 제한
- 화면 중앙 배치
- 넓어진 공간은 여백으로 적극 활용

PC라는 이유로 화면을 불필요하게 채우지 않는다.

---

# 11. 사용하지 않는 스타일

다음 스타일은 사용하지 않는다.

- 라운드 UI
- `border-radius`
- Pill 형태 UI
- 둥근 버튼
- 둥근 카드
- 둥근 Input
- 포인트 컬러
- 그라데이션
- 화려한 그림자
- 불필요한 카드 UI
- 장식 목적의 아이콘
- 복잡한 배경
- 과도한 애니메이션
- 화면을 채우기 위한 불필요한 요소

외부 UI 라이브러리를 사용하는 경우에도 위 스타일이 자동으로 적용되지 않도록 한다.

---

# 12. 핵심 원칙

> 디자인을 추가하기보다 제거하는 방향을 우선한다.

새로운 UI 요소를 추가하기 전에 다음을 확인한다.

- 정말 필요한가?
- 여백과 타이포그래피만으로 해결할 수 없는가?
- 사용자의 현재 행동에 도움이 되는가?
- 기존 UI 패턴을 재사용할 수 없는가?

## 절대 규칙

1. 컬러를 사용하지 않는다.
2. 라운드 UI를 사용하지 않는다.
3. 그림자를 사용하지 않는다.
4. 불필요한 장식 요소를 추가하지 않는다.
5. 여백, 타이포그래피, 선으로 정보 위계를 표현한다.
6. 서비스 전체에서 동일한 스타일과 패턴을 유지한다.
