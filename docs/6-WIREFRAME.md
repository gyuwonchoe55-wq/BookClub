# 와이어프레임 (Wireframe)

## 문서 목적

이 문서는 독서모임 진행 서비스 MVP의 주요 화면 구조와 정보 배치를 정의한다.

상세한 디자인을 확정하는 문서가 아니라,
각 화면에서 사용자가 확인해야 하는 정보와 수행해야 하는 행동을 정의하는 것을 목적으로 한다.

서비스는 모바일과 PC에서 모두 사용할 수 있는 반응형 웹으로 구현한다.

---

# 1. 공통 설계 원칙

## 독서모임방 중심

독서모임방을 서비스의 홈으로 사용한다.

사용자는 독서모임방에서 다음 행동을 시작할 수 있다.

- 참여자 초대
- 현재 회차 확인
- 독서 기록 작성
- 모임 시작
- 지난 회차 확인
- 새 회차 생성

## 현재 해야 할 행동 강조

한 화면에 여러 행동을 동일하게 강조하지 않는다.

현재 상황에서 사용자가 해야 할 가장 중요한 행동을 Primary Action으로 제공한다.

예:

- 독서 기록 미작성 → `독서 기록 작성하기`
- 기록 작성 완료 → `작성한 기록 보기`
- 모임 진행 준비 완료 → `모임 시작하기`

## 진행 화면 단순화

모임이 시작된 이후에는 관리 기능을 최소화하고 현재 대화에 집중할 수 있도록 한다.

## 반응형 웹

모바일에서는 콘텐츠를 세로로 배치한다.

PC에서는 콘텐츠 영역의 최대 너비를 제한하거나 일부 정보를 좌우로 배치하여 넓은 화면을 활용한다.

```text
│                              │

│   독서모임을 시작해보세요.      │

│                              │
│   [ 독서모임 만들기 ]          │

```

→ S02 독서모임 생성

# 4. S03 독서모임방

## 목적

서비스의 중심 허브 화면이다.

사용자가 현재 독서모임 상태를 확인하고 다음 행동을 결정한다.

```text

│                              │

│  │  이번 모임              │  │
│  │                        │  │
│  │  불편한 편의점          │  │
│  │  8월 30일               │  │
│  │                        │  │
│  │  모임 전                │  │
│  └────────────────────────┘  │
│                              │
│  함께하는 사람  3명           │
│                              │
│  ● 규원 👑  작성완료          │
│  ● 민지     작성완료          │
│  ● 철수     미작성            │

│  [ 친구 초대하기 ]            │

│  나의 독서 기록               │
│                              │

│                              │

│                              │

│                              │
```

## 정보 우선순위

1. 현재 회차
2. 참여자 및 기록 작성 현황
3. 내 독서 기록
4. 모임 시작
5. 지난 회차 / 새 회차

---

## 모임장

표시 기능:

- 참여 링크 공유
- 독서 기록 작성/수정
- 참여자별 작성 현황
- 모임 시작
- 지난 회차
- 새 회차 생성

## 참여자

표시 기능:

- 현재 회차
- 참여자 현황
- 독서 기록 작성/수정
- 지난 회차

모임 시작 및 새 회차 생성은 제공하지 않는다.

# 13. PC 반응형 기준

모바일과 PC에서 별도의 화면 구조를 만들지 않는다.

동일한 콘텐츠와 기능을 유지하면서 화면 너비에 따라 배치만 변경한다.

## 모바일

```text
┌───────────────┐
│ 현재 회차      │
├───────────────┤
│ 참여자         │
├───────────────┤
│ 내 독서 기록   │
├───────────────┤
│ 주요 행동      │
└───────────────┘
```

콘텐츠를 한 열로 배치한다.

## PC

```text
┌─────────────────────────────────────┐
│              모임 정보               │
├──────────────────────┬──────────────┤
│                      │              │
│    현재 회차          │   참여자      │
│                      │              │
│    내 독서 기록       │   초대        │
│                      │              │
├──────────────────────┴──────────────┤
│              주요 행동               │
└─────────────────────────────────────┘
```

화면이 넓은 경우 주요 정보를 2열로 배치할 수 있다.

단, 모바일과 PC에서 기능이나 정보 구조 자체를 다르게 만들지 않는다.

# 14. MVP 화면 우선순위

개발 시 모든 화면을 동일한 수준으로 구현하지 않는다.

### 최우선

- S03 독서모임방
- S05 독서 기록
- S06 모임 진행

서비스의 핵심 가치 검증에 직접적으로 영향을 주는 화면이다.

### 기본

- S01 랜딩
- S02 독서모임 생성
- S04 참여하기
- S07 모임 종료
- S08 새 회차 생성

핵심 기능을 사용할 수 있을 정도로 단순하게 구현한다.

# 15. 와이어프레임 원칙

- 독서모임방을 서비스의 중심 화면으로 한다.
- 한 화면에서 가장 중요한 행동 하나를 명확하게 강조한다.
- 모임 진행 중에는 현재 대화에 집중할 수 있도록 불필요한 요소를 최소화한다.
